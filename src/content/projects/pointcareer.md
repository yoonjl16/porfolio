## 문제

경기대학교 학생은 교내 비교과 활동으로 **포인트**를 모읍니다. 하지만 활동 정보가 여러 곳에 흩어져 있어서 **진로와 상관없는 활동으로 포인트만 채우는** 경우가 많았습니다. 학교로 들어오는 추천 채용 공고도 일반 채용 사이트에는 올라오지 않아 놓치기 쉬웠습니다.

> "의미없는 포인트 활동으로 시간 낭비하고 있나요?" — 앱 온보딩 첫 화면 문구

## 해결

**진로와 연결된 활동으로 포인트도 채우고 경력도 쌓는** 앱을 만들었습니다.

- **맞춤형 추천** — 관심 분야(IT/소프트웨어, 교육, 공공기관 등 업종), 원하는 활동 유형, 포인트를 모을 기한을 입력하면 효율적인 활동 묶음("나만의 진로 맞춤 포인트 플랜")을 추천
- **포인트 활동 둘러보기** — 활동별 포인트, 소요 시간, 온·오프라인 여부, 카테고리를 보여주고 최신순·인기순 정렬과 검색 지원. 상세 화면에서 신청 링크로 바로 이동
- **학교 추천 채용 공고** — 경기대 전용 추천 채용 공고 목록, 검색, 상세 정보
- **마이페이지** — 학과·학년 프로필, 저장한 KGU 프로그램과 채용 공고 북마크 관리

## 내가 한 일

Flutter로 **앱 클라이언트 전체**를 만들고 백엔드 REST API와 연동했습니다.

- **화면 17개 구현** — 온보딩, 약관 동의, 이메일 인증, 회원가입, 프로필 설정, 로그인, 하단 탭 내비게이션, 홈, 추천 입력 → 로딩 → 추천 결과, 활동·채용 목록과 상세, 마이페이지
- **인증 흐름** — 이메일 인증번호(6자리) 요청·확인 → 회원가입(비밀번호 규칙 검증, 재확인) → 로그인 후 받은 액세스 토큰을 화면 간에 전달하고, 인증이 필요한 API 요청 헤더에 붙여 사용
- **API 연동** — 인증, 사용자 정보, 포인트 활동(목록·정렬·검색·상세·추천), 채용 공고(목록·검색·상세), 북마크(생성·삭제) 등 15개 이상의 엔드포인트를 연결하고, 응답 JSON을 Dart 모델 클래스로 변환
- **북마크 동기화** — 활동과 채용 공고 두 종류의 북마크를 하나의 API로 다루고, 등록·삭제 후 상세 화면과 마이페이지를 서버 최신 상태로 다시 불러와 화면과 데이터가 어긋나지 않게 처리
- **멀티 플랫폼 배포** — Android 릴리스 빌드, GitHub Actions로 iOS IPA 빌드 자동화, Firebase Hosting으로 웹 버전 배포

## 배운 점

- **서버 응답은 언제든 비어 있을 수 있다** — 응답 필드가 없거나 형식이 다를 때를 대비해 모델 변환 시 기본값을 두고, 로딩·실패·결과 없음 상태를 화면마다 따로 처리했습니다. 백엔드와 API 명세를 먼저 맞추는 것이 연동 속도를 좌우한다는 걸 배웠습니다.
- **하나의 코드로 여러 플랫폼에 배포하는 과정** — Flutter 코드 하나로 Android·iOS·웹을 모두 빌드하면서, 플랫폼별 서명과 빌드 설정을 CI로 자동화하는 경험을 했습니다.
